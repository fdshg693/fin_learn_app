# docs

プロジェクトドキュメントの目次。

## フォルダ構成

- [DDD/](DDD/) — ドメインモデルの定義・用語集・ドメインルール
- [FEATURES/](FEATURES/) — 機能単位の詳細ドキュメント。1機能 = 1サブフォルダ
- [MEMO/](MEMO/) — 開発メモ・作業ノート（ユーザー管理・AIは触らない）
- [OLD/](OLD/) — 履歴保存のための旧ドキュメント置き場(現役の参照対象ではない)

## トップ直下のフォルダ・ファイル

- [API/](API/) — バックエンドAPI全体の横断ドキュメント（責務別に分割）
- [FRONT.md](FRONT.md) — フロントエンド全体の横断ドキュメント

機能個別の詳細は `FEATURES/<機能名>/` に置き、横断的な仕様はトップ直下に置く。

## ファイル名の慣習

### FEATURES/ 配下

機能ごとにサブフォルダを切り、その中をレイヤー別に分割する。

- `LOGIC.md` — ドメインロジック層
- `API.UI.md` — API層 + フロントエンドUI層
- `INFRASTRUCTURE.md` — インフラ層(外部I/O等)

必要なレイヤーのファイルだけを置けばよい(全レイヤー必須ではない)。

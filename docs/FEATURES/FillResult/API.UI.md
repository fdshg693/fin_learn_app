# 約定結果 — API・UI

> 約定ロジックの詳細は [LOGIC.md](./LOGIC.md) を参照。

## 設計方針

`FillResult` / `OrderFill` はバックエンド内部の概念であり、フロントエンドには**直接公開しない**。
クライアントにはプレイヤー向けの集約済み約定結果（`TradeResultDto`）を返す。
個別の `OrderFill`（どの待機注文と何株マッチしたか）は公開しない。

## API が返す約定関連情報

| 情報 | 提供元 | 説明 |
|---|---|---|
| 更新後の現金残高 | `player.cash` | 約定金額 + 手数料が反映済み |
| 更新後のポジション一覧 | `player.positions` | 数量ゼロのポジションは除外 |
| 総資産額 | `player.totalAssets` | 現金 + 全ポジション評価額 |
| 損益 | `player.profitLoss` | 初期資産との差分 |
| 直近の約定結果 | `recentTrades` | 直近3件の約定サマリ（後述） |
| 警告メッセージ | `warning` | 約定失敗・部分約定時の理由（後述） |

### 約定結果の履歴（`recentTrades`）

バックエンドがゲームごとに直近 3 件の `TradeResult` を保持し、`GameResponse.recentTrades` として返す。

| フィールド | 型 | 説明 |
|---|---|---|
| `instrumentId` | int | 銘柄 ID |
| `side` | string | `"Buy"` / `"Sell"` |
| `filledQuantity` | int | 約定数量 |
| `totalAmount` | int | 約定金額 |
| `fee` | int | 手数料 |

- `TurnProcessor` が `TradeResult?` を返却 → 約定成功時のみ `GameStore.AddTrade` で履歴に追加
- 待機（Wait）や失敗時は `TradeResult` が `null` のため履歴に追加されない
- 4 件目以降は古い順に破棄（FIFO）

### 約定操作を伴うエンドポイント

| 操作 | 説明 |
|---|---|
| 買い注文 | 指定銘柄・数量・価格で買い注文を発行し、板とマッチング |
| 売り注文 | 指定銘柄・数量・価格で売り注文を発行し、板とマッチング |
| 待機 | 注文を出さずにターンを進める（約定は発生しない） |

いずれも応答は同一形式で、ゲーム全体の最新状態を返す。

## UI が表示する約定フィードバック

### 約定結果テーブル（TradeHistory コンポーネント）

`recentTrades` が空でない場合、直近の約定結果をテーブルで表示する（新しい順）。

| 列 | 説明 |
|---|---|
| 売買 | 買（赤）/ 売（青）|
| 銘柄 ID | 対象銘柄 |
| 約定数量 | 約定した株数 |
| 約定金額 | 約定合計金額（JPY） |
| 手数料 | 手数料（JPY） |

約定がまだ一度もない場合はテーブル自体を非表示にする。

### 状態変化による暗黙フィードバック

約定テーブルに加え、以下の状態変化でもユーザーに結果を伝える:

- **現金残高**の増減
- **ポジション一覧**の数量変化（新規追加 or 数量増減 or 消滅）
- **総資産・損益**の更新

### 失敗・警告時

`warning` が非 null の場合、警告メッセージを表示する。

| ケース | 警告内容 |
|---|---|
| 成行注文で対当注文なし | マッチする注文がない旨 |
| 資金不足 | 現金残高が足りない旨 |
| 保有数量不足 | 売却に必要な株数がない旨 |

警告時はポートフォリオ不変（取引が成立していない）。
次の操作で警告は自動的にクリアされる。

## 表示しない情報

以下は意図的にクライアントへ公開していない:

- 個別の `OrderFill`（注文ID・約定数量・約定金額）
- 約定価格の内訳（どの待機注文と何株マッチしたか）
- 更新後の `OrderBook` の中身（板情報は別パネルで参照可能）
